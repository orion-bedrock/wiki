A plugin adds features to Orion without changing Orion itself: commands, minigames, menus, custom items, a balancer for your network, a rule that keeps bots out. You write it in C#, Orion loads it when it starts, and it talks to Orion through an SDK: a set of ordinary C# types (`Player`, `World`, `Server`…) with methods and events.

## Two applications, two SDKs

Orion runs as two applications, and a plugin is written for one of them:

| Application | What it is | A plugin can | SDK |
|---|---|---|---|
| [Server](../server/plugins/) | A Minecraft Bedrock server: worlds, players, blocks, items, mobs | Handle game events, add commands, change blocks and entities, show forms and menus, add items, blocks and mobs | `Orion.Server.Sdk` |
| [Proxy](../proxy/plugins/) | The gateway in front of several servers: players connect to it, and it moves them between servers and groups | Choose where players go, move them between servers, guard logins, put servers into maintenance, add network commands | `Orion.Proxy.Sdk` |

A plugin references one SDK, never both. Plugins of a server and plugins of its proxy can still work together: they exchange messages about a player.

## How a plugin runs

- A plugin is a .NET class library published with **Native AOT** as a native shared library (`.dll`, `.so` or `.dylib`). It does not need a .NET runtime on the machine and starts instantly.
- Orion opens the library once, when it starts, and calls your plugin class at each step of its life: `OnLoad`, `OnEnable` and `OnDisable`.
- Everything else happens through the SDK: you read and change the objects of Orion, register commands and tasks, and handle events. What you register is removed for you when the plugin is disabled.
- An exception your code throws never brings Orion down: it is logged, and a plugin that fails too often is disabled.
- A plugin is updated by replacing its files and restarting Orion; libraries are never unloaded while Orion runs.

## Start here

1. Follow [Getting started](../server/plugins/basics/getting-started/) for a server plugin, or [Getting started](../proxy/plugins/basics/getting-started/) for a proxy plugin.
2. Read [The life of a plugin](../server/plugins/basics/lifecycle/) to know what to do at each step.
3. Keep [Native compilation](native-aot/) and [Errors and limits](errors/) open while you build.
4. Use [plugin.json](plugin-json/) when you add dependencies or change the manifest.
